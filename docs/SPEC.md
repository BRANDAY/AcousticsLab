# AcousticsLab — спецификация проекта на Unreal Engine 5

Учебно-демонстрационный проект: реализация методов геометрической акустики из работ **Marjan Sikora (FESB, Split)** в Unreal Engine 5 и их сравнение с индустриальными решениями (**Steam Audio** от Valve и **Audio Tracing** от Pinpoint с Fab) на одной и той же геометрии.

Документ — техническое задание проекта. Идентификаторы кода, имена классов и файлов — на английском; пояснения — на русском.

---

## 0. Что должно получиться

Запускается проект → главное меню (UMG):

```
ACOUSTICS LAB
├── 1. Methods of M. Sikora
│   ├── 1.1 Image sources & beam tracing        (Level_Shoebox, Level_Amphitheatre)
│   ├── 1.2 Beam tracing with refraction        (Level_Refraction)
│   ├── 1.3 Thread-level parallelization        (benchmark panel, any level)
│   ├── 1.4 Hybrid beam/ray tracing             (comparison panel)
│   └── 1.5 Audio AR soundwalk (optional)       (Level_Amphitheatre, soundwalk mode)
├── 2. Industry
│   ├── 2.1 Steam Audio (Valve)                 (Level_Amphitheatre_SteamAudio)
│   └── 2.2 Audio Tracing (Pinpoint, Fab)       (Level_Amphitheatre_AudioTracing)
├── 3. Compare                                  (metrics table, A/B listening)
└── Quit
```

Каждый пункт раздела 1 — это **визуально показанный алгоритм**: видно лучи/пучки, видно отражения, видно импульсный отклик и метрики, слышно результат (свёрточная реверберация). Раздел 2 — те же сцены с готовыми плагинами. Раздел 3 — таблица метрик и переключатель A/B.

Проект **не претендует на научный результат** — это стенд, чтобы понять методы и иметь, что показать потенциальному научному руководителю.

## 2. Физика и математика (что именно считаем)

### 2.1 Общие допущения
- Геометрическая акустика: длина волны ≪ размеров поверхностей. Дифракцию в первой версии не реализуем (отдельный опциональный пункт).
- Энергетическая модель: лучи/пучки переносят энергию, фазу не учитываем. Результат — **энергетический импульсный отклик** `E(t)` (гистограмма энергии по времени).
- Скорость звука `c = 343 м/с` в воздухе; для преломления вторая среда с `c2` (вода 1480 м/с) — см. §2.6.
- Материалы: коэффициент поглощения `α ∈ [0,1]` и рассеяния `s ∈ [0,1]`. В первой версии — широкополосные (одно число); расширение до 6 октавных полос (125 Гц … 4 кГц) — опция `NumBands` в коде с самого начала (массив вместо скаляра).
- Единицы: внутри солверов — **метры и секунды** (UE работает в сантиметрах; конвертация только на границе UE ↔ ядро).

### 2.2 Стохастический ray tracing (базовый солвер `FRayTracer`)
1. Из источника испускаем `N` лучей (по умолчанию 20 000; равномерно по сфере — Fibonacci sphere), энергия каждого `E0 = 1/N`.
2. Луч летит до ближайшего треугольника (BVH, §3.3). Время `t += d / c`.
3. В точке удара: `E *= (1 − α)`. Направление: с вероятностью `s` — диффузное (косинусное распределение Ламберта вокруг нормали), иначе зеркальное.
4. Воздушное поглощение (опция): `E *= exp(−m·d)`, `m` по полосам (для широкополосной версии `m = 0.002 /м`).
5. Приёмник — сфера радиуса `r = 0.5 м` (параметр). Если отрезок луча пересекает сферу, в гистограмму в бин `t_hit = (накопленный путь до точки входа) / c` добавляется текущая `E`. Направление луча не меняется (приёмник «прозрачный»).
6. Луч останавливается, если `E < E0·1e-6`, `t > T_max` (3 с) или порядок отражения > `MaxOrder` (200).
7. Прямой звук считаем аналитически и добавляем отдельно: `E_direct = (r² / (4 d²))` при `t = d/c`, если отрезок источник–приёмник не перекрыт (один line trace). Это согласовано с подсчётом попаданий лучей: сфера сечением `πr²` на расстоянии `d` перехватывает долю `πr²/(4πd²)` общей энергии.
8. Гистограмма: шаг `Δt = 1 мс`, длина `T_max / Δt` бинов, по полосам.

### 2.3 Метрики из гистограммы (`FRoomMetrics`)
- Кривая затухания Шрёдера: `EDC(t) = Σ_{τ≥t} E(τ)`, `L(t) = 10·log10(EDC(t)/EDC(0))` дБ.
- `EDT = 6 · (t(−10 дБ) − t(0 дБ))`
- `T20 = 3 · (t(−25) − t(−5))`, `T30 = 2 · (t(−35) − t(−5))` — по линейной регрессии на участке, не просто по двум точкам.
- `C50 = 10·log10( Σ_{t<50 мс} E / Σ_{t≥50 мс} E )`, `C80` аналогично с 80 мс. Отсчёт `t` от прихода прямого звука.
- `D50 = Σ_{t<50 мс} E / Σ E`.
- `Ts` (центр тяжести) — опционально.
- Эталон для валидации в прямоугольной комнате: Sabine `T60 = 0.161·V/(S·ᾱ)`, Eyring `T60 = 0.161·V/(−S·ln(1−ᾱ))`. Для комнаты 10×7×3 м (`V = 210 м³`, `S = 242 м²`) и `α = 0.1`: Sabine 1.40 с, Eyring 1.33 с.

### 2.4 Метод мнимых источников (`FImageSourceSolver`)
Детерминированные ранние отражения, математическая основа beam tracing.
- Для каждой плоской поверхности `P_i` мнимый источник `S' = mirror(S, P_i)`; для порядка `k` — последовательность отражений `(P_i1 … P_ik)`.
- Проверка валидности: обратная трассировка от приёмника к `S'_k`: точка пересечения с плоскостью `P_ik` должна лежать внутри многоугольника и не быть перекрытой; далее к `S'_{k−1}` и т.д.
- Энергия: `E = Π(1 − α_i) · r² / (4 d'²)`, где `d'` — расстояние от приёмника до валидного мнимого источника; `t = d'/c`.
- Ограничение: порядок ≤ 3 (экспоненциальный рост). В UI — порядок как слайдер, мнимые источники рисуются сферами, пути — ломаными.

### 2.5 Beam tracing по Сикоре (`FBeamTracer`)
Пучок = вершина (реальный или мнимый источник) + треугольное сечение (три направляющих луча). Пучок трассируется как единое целое; видимость закодирована в самом пучке — поэтому нет пропусков отражений, характерных для стохастических лучей (аргумент из S2/S4).

Алгоритм (упрощённо по S1):
1. **Старт**: сфера вокруг источника разбивается на треугольные пучки — икосаэдр с `SubdivisionLevel` подразбиениями (0 → 20 пучков, 2 → 320, 3 → 1280).
2. **Трассировка пучка**: найти треугольники сцены, попадающие в пучок (запрос к BVH по фрустуму пучка). Ближайший слой геометрии определяет, что пучок «видит».
3. **Деление пучка (beam division, ядро S1)**: сечение пучка проецируется на плоскость попавшего треугольника; выполняется клиппинг (Sutherland–Hodgman) многоугольника сечения по рёбрам треугольника. Каждый клиппированный кусок — дочерний пучок с той же вершиной; если кусок не треугольник, его триангулируем веером. Части сечения, не накрытые геометрией, продолжают лететь (становятся отдельными дочерними пучками, если дальше есть геометрия).
4. **Отражение**: вершина дочернего пучка = зеркальное отражение вершины относительно плоскости треугольника; направляющие лучи — отражённые. Энергия `E *= (1 − α)`.
5. **Дерево пучков**: узел = {apex, 3 направляющих луча, плоскость последнего отражения, порядок, накопленный коэффициент, ссылка на треугольник}. Глубина ≤ `MaxBeamOrder` (3–6).
6. **Приёмник**: для каждого листа и узла — проверка «точка внутри пучка» (три полупространства + «за плоскостью последнего отражения»). Если внутри, путь валиден автоматически: `d' = |R − apex|`, `t = d'/c`, `E = Π(1−α_i) · r²/(4d'²)`. Это и есть преимущество пучков: не нужна обратная трассировка, как в §2.4.
7. **Движущийся приёмник**: дерево строится один раз для неподвижного источника; при движении приёмника пересчитывается только §2.5.6 — именно это подчёркивает S2.
8. Рассеяние и дифракция — не реализуем в v1 (в S2 есть; оставить `TODO` с ссылкой на раздел статьи).

Ожидаемая слабость (её автор сам описывает в диссертации): число пучков взрывается на высоких порядках. Это мотивирует §2.7 и §2.8.

### 2.6 Преломление (`FBeamTracer` с `bRefraction`)
Сцена делится на среды (`FMedium {c, density}`), границы сред — треугольники с флагом `bInterface` и ссылками на среду с каждой стороны.
- Направляющие лучи пучка преломляются по Снеллиусу: `sin θ2 / sin θ1 = c2 / c1`. Полное внутреннее отражение при `sin θ2 > 1` → пучок только отражается.
- Преломлённый пучок **не имеет единой вершины** (S2, и отдельная статья автора 2010 г. «refraction as a non-linear transformation»). Приближение для демо: новая вершина = точка, минимизирующая сумму квадратов расстояний до трёх преломлённых направляющих лучей (МНК-пересечение). Это допущение фиксируем в UI и в README как известное упрощение.
- Энергия на границе: коэффициент пропускания `T = 1 − R`, где `R` — по импедансам сред (`Z = ρ·c`): `R = ((Z2−Z1)/(Z2+Z1))²` при нормальном падении (для демо достаточно).
- Демо-сцена `Level_Refraction`: бассейн 20×10×3 м, источник над водой, сетка приёмников под водой; второй вариант — «акустическая линза» как в S2 (сферическая граница сред): наглядно видно фокусировку пучков.

### 2.7 Параллелизация (`FParallelBeamTracer`, по S3)
- Корневые пучки (и их поддеревья) независимы → распределяются по потокам. Каждый поток пишет в свою гистограмму; в конце — редукция.
- Количество потоков задаётся явно (1, 2, 4, 8, …, `FPlatformMisc::NumberOfCores()`): используем собственный `FQueuedThreadPool` с заданным числом потоков (у `ParallelFor` число потоков не задаётся), работа режется на задачи по корневым пучкам.
- Ускоряющая структура: BVH (§3.3) с переключателем `bUseBVH` (без BVH — перебор всех треугольников), чтобы показать второй источник ускорения из S3 (у автора — октодерево; BVH даёт тот же эффект, это оговаривается в UI).
- Бенчмарк: прогоны для каждого числа потоков × {BVH, brute force} × 3 повторения; результат — таблица и график speedup = `T1 / Tn`; экспорт CSV.

### 2.8 Гибрид beam/ray (`FHybridTracer`, по S4)
- Ранняя часть: `FBeamTracer` до порядка `K` (по умолчанию 2) или до времени `t_mix` (80 мс) — что наступит раньше.
- Поздняя часть: `FRayTracer`, но вклады, которые уже учтены пучками (чисто зеркальные пути порядка ≤ K), **исключаются**: луч начинает писать в гистограмму только с порядка `K+1` либо после первого диффузного отражения.
- Итоговая гистограмма = ранняя (пучки) + поздняя (лучи). Панель сравнения показывает три кривые: pure ray / pure beam (до K) / hybrid, и метрики для каждой.

### 2.9 Синтез импульсного отклика для прослушивания (`FIRSynthesizer`)
- Из энергетической гистограммы делаем сигнал: для каждого бина — белый шум (или пуассоновская последовательность импульсов), умноженный на `sqrt(E(bin))`; детерминированные вклады (прямой звук, ранние отражения из пучков/мнимых источников) вставляем как отдельные импульсы с точной задержкой (субсэмпловая интерполяция не нужна).
- Частота дискретизации 48 кГц, моно; нормализация по пику −3 дБFS; длина — до точки, где `L(t) < −60 дБ`, но не более `T_max`.
- Экспорт в WAV (`Saved/IR/<Level>_<Solver>_<ReceiverId>.wav`).
- Применение в UE: создать `UAudioImpulseResponse` в рантайме (`NewObject`, заполнить `ImpulseResponse`, `NumChannels=1`, `SampleRate=48000`) и назначить в `USubmixEffectConvolutionReverbPreset::SetImpulseResponse()`. Если рантайм-создание окажется ненадёжным — запасной путь: импорт WAV как IR-ассет в редакторе и выбор ассета из списка.

## 3. Архитектура проекта

### 3.1 Общие параметры
- UE **5.8.3** (актуальная версия на момент написания). C++ проект, шаблон Blank, без стартового контента. Плагин Audio Tracing по листингу Fab поддерживает UE 5.6 и 5.7.2+ («или новее») — перед вехой M9 проверить в листинге, что 5.8 есть в списке совместимых; для Steam Audio взять релиз под 5.8 или собрать из исходников (см. §3.8, §6).
- Платформа: Windows 10/11, DX12, GPU с аппаратным RT (нужен плагину Audio Tracing; собственные солверы — CPU).
- Плагины: `GeometryScripting`, `ProceduralMeshComponent`, `Niagara` (опционально для лучей), `EnhancedInput`, `SteamAudio`, `AudioTracing` (Fab), `AudioCapture` (для записи A/B).

Audio Tracing работает своими компонентами. На вехе M9 проверить, что оба плагина уживаются в одном проекте; если нет — два профиля конфигурации (`DefaultEngine.ini` варианты) с перезапуском, о чём сообщает UI.

### 3.3 Геометрия и ускорение
- `FAcousticTriangle { FVector3d V0,V1,V2; FVector3d N; int32 MaterialId; int32 MediumFront, MediumBack; bool bInterface; }`
- `FAcousticScene { TArray<FAcousticTriangle>; TArray<FAcousticMaterialProps>; TArray<FMedium>; FBVH Bvh; }`
- `FBVH`: бинарное дерево, разбиение по медиане/SAH, листья по 4–8 треугольников; запросы: `IntersectRay`, `QueryFrustum(плоскости пучка)`, `QueryAABB`. Тест: результаты совпадают с перебором на 10k случайных лучей.
- Извлечение геометрии из уровня (`UAcousticSceneExtractorComponent`): все `UStaticMeshComponent`/`UDynamicMeshComponent` с тегом `Acoustic`; треугольники берутся из `UStaticMesh::GetRenderData()->LODResources[0]` (у ассетов включить **Allow CPU Access**) или из `UDynamicMesh`; трансформ в мировые координаты; **см → м**. Материал: по тегу компонента `AcMat:<name>` или по `UAcousticMaterialAsset`, назначенному в `ALevelSetupActor` по имени меша. Дефолт — `Concrete (α=0.03, s=0.1)`.
- Материалы (DataAsset `UAcousticMaterialAsset`): Concrete/Stone α 0.02–0.05; Plaster 0.05; Wood 0.1; Audience/seated people 0.6–0.8; Water surface (interface); Absorber 0.9. Пресеты как ассеты в `Content/Acoustics/Materials/`.

| `Level_MainMenu` | меню | пустой уровень + UMG |
| `Level_Shoebox` | валидация: прямоугольная комната 10×7×3 м, настраиваемый α | 6 плоскостей из кубов/Geometry Script; аналитические T60 выводятся рядом с рассчитанными |
| `Level_Amphitheatre` | «герой»: эллиптический амфитеатр в духе Салоны: арена ~65×40 м, кавея из 20 ступенчатых рядов, высота ~15 м; опционально велариум (тент) как поглощающая крышка | Geometry Script: эллипсы → экструзия рядов; материалы «камень», опция «зрители» (α рядов 0.7) |
| `Level_Refraction` | §2.6: бассейн и линза | Geometry Script; граница сред — отдельный меш с тегом `Interface` |
| `Level_Amphitheatre_SteamAudio` | тот же амфитеатр, Steam Audio | копия уровня + Steam Audio Geometry/Material/Probe Volume, запечённые или real-time отражения |
| `Level_Amphitheatre_AudioTracing` | тот же амфитеатр, Audio Tracing | копия уровня + компоненты плагина по его sample-проекту |

Позиции источника и приёмников во всех амфитеатровых уровнях **одинаковые** и задаются в `DA_AmphitheatrePositions` (DataAsset): источник — центр арены на высоте 1.6 м; приёмники R1 (1-й ряд), R2 (10-й ряд), R3 (20-й ряд), R4 (боковой сектор). Сетка для тепловой карты — по всем рядам с шагом 2 м.

### 3.5 Запуск симуляций
- `UAcousticSimulationSubsystem` хранит последние результаты по уровням/солверам (для панели Compare) и настройки.
- `AAcousticSimulationManager` (один на уровень): собирает сцену (`Extract`), запускает выбранный солвер в фоне (`UE::Tasks::Launch` / `AsyncTask(ENamedThreads::AnyBackgroundThreadNormalTask)`), прогресс в HUD, результат (`FSimulationResult { Histogram, Metrics, Paths (для визуализации, ограничено 2000), BeamTree (опционально), Timing }`) отдаёт на game thread.
- Параметры солвера — `FSolverSettings` (UStruct, редактируется в HUD): `NumRays, MaxOrder, ReceiverRadius, BinMs, TMax, SubdivisionLevel, MaxBeamOrder, HybridK, bRefraction, NumThreads, bUseBVH, bAirAbsorption`.

### 3.6 Визуализация
- **Лучи**: `ULineBatchComponent` / `DrawDebugLine` для ≤ 2000 путей, цвет по порядку отражения (0 — белый, 1 — жёлтый, 2 — оранжевый, 3+ — красный), прозрачность по энергии. Режим «только пути, дошедшие до приёмника».
- **Мнимые источники**: сферы (`UInstancedStaticMeshComponent`), цвет по порядку, путь к приёмнику — ломаная.
- **Пучки**: фрустумы как полупрозрачные меши (`UDynamicMeshComponent`, по одному на порядок, цвет по порядку); слайдер «порядок» и «показать только пучки, содержащие приёмник». Для преломления — пучок до и после границы разными цветами.
- **Тепловая карта**: сетка приёмников → `UInstancedStaticMeshComponent` плиток 1×1 м с per-instance custom data = значение метрики → материал с градиентом (viridis). Выбор метрики в HUD: SPL прямого звука, C80, T30, EDT.
- **Импульсный отклик**: `UIRPlotWidget` (UMG, `OnPaint` + `FSlateDrawElement::MakeLines`): энергия в дБ по времени, кривая Шрёдера, отметки −5/−35 дБ, 50/80 мс; наложение до 3 кривых (для Hybrid/Compare).
- **HUD**: параметры солвера, кнопки Run/Stop, метрики выбранного приёмника, время расчёта, число лучей/пучков/узлов дерева.

### 3.7 Прослушивание (аурализация)
- `UAuralizationComponent`: держит безэховый клип (речь, 5–10 с; любой CC-лицензированный безэховый файл, положить в `Content/Audio/Anechoic/`), submix `SM_Auralization` с `Convolution Reverb`; по результату симуляции строит IR (§2.9) и назначает.
- Переключение приёмника R1…R4 — мгновенная смена IR (пучковое дерево не пересчитывается, §2.5.7).
- A/B: `Dry` / `Ray` / `Beam` / `Hybrid` / (в Industry) `SteamAudio` / `AudioTracing` — горячие клавиши 1–6.
- Слушатель в уровнях Sikora — камера от первого лица (бесплатный «soundwalk»: ходим по рядам, слышим изменение). Это же — основа пункта 1.5.

### 3.8 Раздел Industry
- **Steam Audio** (Valve; open source, Apache 2.0; плагин для Unreal: https://valvesoftware.github.io/steam-audio/ и https://github.com/ValveSoftware/steam-audio/releases). Настройка: включить плагин; Project Settings → Audio → Spatialization/Reverb/Occlusion = Steam Audio; на мешах — `Steam Audio Geometry` + `Steam Audio Material`; `Steam Audio Probe Volume` → генерация проб → bake (или real-time reflections); источник — `Steam Audio Source` с Reflections = on; слушатель — `Steam Audio Listener`. Если текущий релиз плагина не поддерживает 5.8 «из коробки» — собрать плагин из исходников (он поставляется с исходниками), это фиксируется как риск.
- **Audio Tracing** (Pinpoint, бесплатно на Fab: https://www.fab.com/listings/8334fed3-f232-4b2f-a250-25f3b150f65c). По листингу требует UE 5.6 или 5.7.2 и новее (5.7.0/5.7.1 не поддерживаются), DX12 RT; перед установкой на 5.8.3 сверить список версий в листинге. Настройка — по sample-проекту из листинга; глубина отражений — через его console variable. Геометрия берётся из мира, отдельные occlusion-объёмы не нужны.
- **Сравнение (M9, опционально)**: у плагинов нет публичного API для выдачи импульсного отклика, поэтому: воспроизводим короткий щелчок (1 сэмпл при 48 кГц, или sine sweep) через источник, записываем выход мастер-сабмикса (`USoundSubmix::StartRecordingOutput/StopRecordingOutput` → WAV), из записи получаем приближённый IR и считаем те же метрики (§2.3). Для sweep — деконволюция (опционально). Это даёт честную таблицу: свой ray / beam / hybrid vs Steam Audio vs Audio Tracing на одинаковых позициях.

## 4. Вехи (milestones) и критерии приёмки

Каждая веха: компилируется (`Build.bat`, см. раздел Quick start в `README.md`), автотесты зелёные, есть короткий `docs/milestones/Mx.md` с тем, что сделано и скриншотом. Коммит на веху.

| Веха | Содержание | Критерий приёмки |
|---|---|---|
| **M0** Setup | Проект, модули, плагины, папки, `Level_MainMenu` с UMG-меню и загрузкой уровней-заглушек, `ALevelSetupActor`, Enhanced Input (WASD + мышь, 1–6, Esc → меню) | Меню открывается при старте, все пункты грузят уровни и возвращаются в меню |
| **M1** Geometry | `FAcousticScene`, извлечение из уровня, материалы-ассеты, `FBVH`, `Level_Shoebox` | Тест BVH = перебор на 10k лучей; извлечённая комната имеет 12 треугольников и площадь 242 м² |
| **M2** Ray tracer | `FRayTracer`, гистограмма, `FRoomMetrics`, HUD с метриками, валидация | В Shoebox при α=0.1/0.2/0.3 расчётный T30 отличается от Eyring не более чем на 20 %; метрики на синтетическом экспоненциальном затухании точны до 2 % |
| **M3** Visualization | лучи, тепловая карта, `UIRPlotWidget` | Видны пути к приёмнику, тепловая карта C80 по сетке, график IR с кривой Шрёдера |
| **M4** Auralization | `FIRSynthesizer`, WAV-экспорт, Convolution Reverb, A/B Dry/Ray, смена приёмника | Слышна разница между R1 и R3; экспортированный WAV открывается в Audacity и имеет ожидаемую длину |

| **M6** Refraction | `Level_Refraction`, среды, преломление пучков, демо линзы | На бассейне видно преломление на границе и полное внутреннее отражение при больших углах; на линзе видна фокусировка (пятно повышенной энергии на сетке приёмников) |
| **M7** Parallelization | пул потоков, бенчмарк, CSV, график speedup, переключатель BVH | Таблица 1/2/4/8/N потоков × BVH on/off, speedup растёт монотонно; результаты не зависят от числа потоков (детерминированность редукции) |
| **M8** Hybrid | `FHybridTracer`, панель сравнения трёх кривых | Hybrid даёт те же ранние отражения, что pure beam, и тот же хвост (T30 ±5 %), что pure ray |
| **M9** Industry | два уровня с плагинами, A/B, опционально запись щелчка и метрики | Оба уровня звучат; переключение A/B работает; (опц.) таблица Compare заполнена для всех пяти вариантов |
| **M10** Amphitheatre + polish | Geometry Script амфитеатр, опция «зрители/велариум», soundwalk, README с GIF/скриншотами | Полный проход по меню без крашей; README объясняет, что где показано и какие упрощения сделаны |

Ориентировочно: M0–M4 — 2 недели вечерами, M5–M8 — 2–3 недели, M9–M10 — 1–2 недели.

## 5. Эксперименты, которые стоит провести (и записать в README)

1. **Shoebox vs Sabine/Eyring** при α = 0.05, 0.1, 0.2, 0.3, 0.5 — таблица T30. Показывает, что тракт считает правильно.
2. **Сходимость ray tracing** по N (1k…200k лучей): разброс T30 и C80 — ответ на вопрос «сколько лучей нужно».
3. **Пропущенные отражения**: pure ray при малом N vs beam — сколько ранних отражений теряет стохастика (аргумент S2/S4 в цифрах).
4. **Speedup** по потокам и BVH (S3) на амфитеатре при SubdivisionLevel 2–3.
5. **Амфитеатр: пусто vs зрители vs велариум** — C80/T30 по рядам (та же постановка, что у автора для Салоны).
6. **Свой hybrid vs Steam Audio vs Audio Tracing** — метрики из записанного отклика (если M9 опц. сделан) и субъективное A/B.

## 6. Известные упрощения и риски

- Преломлённый пучок с одной вершиной — приближение (§2.6). Честно подписано в UI.
- Нет дифракции и частотно-зависимого рассеяния; нет фазы (энергетическая модель).
- Геометрия из `RenderData` требует Allow CPU Access; в packaged build без него извлечение не сработает — для демо достаточно редактора/PIE и Development-сборки.
- Совместимость плагинов с UE 5.8.3: Audio Tracing заявляет 5.6 и 5.7.2+ — проверить, что 5.8 поддерживается, иначе ждать обновления плагина или держать для раздела Industry отдельный проект на поддерживаемой версии; Steam Audio может требовать сборки из исходников под 5.8. Если оба одновременно не живут в одном проекте — два профиля конфигурации.
- Рантайм-создание `UAudioImpulseResponse` может потребовать вызова приватных методов — запасной путь через импорт WAV.
- Извлечение IR из плагинов — только косвенно (запись отклика на щелчок).
