## Plan

### Findings before coding (15.10.2026)

- **Audio Tracing** (Pinpoint, Fab listing 8334fed3-…): the listing's compatibility block says "Unreal Engine 5.6 – 5.8"
  (last update 21.07.2026; the description text still says 5.6 / 5.7.2+). Requirements from its documentation
  (https://teampinpoint.gitbook.io/audio-tracing-docs): hardware ray tracing (*Support Hardware Ray Tracing*, *Use
  Hardware Ray Tracing when available*), Lumen GI or reflections, Windows / DX12, Project Settings → Windows → Audio:
  *Spatialization Plugin* = Audio Tracing Spatializer, *Source Data Override Plugin* = Audio Tracing; a Sound Attenuation
  with *Plugin-Spatialized* + *Enable Source Data Override*; an *Audio Tracing Sound Material* component under each
  primitive; reflection depth through the CVar `AudioTracing.HardwareRayTracing.MaxReflectionDepth`. Installed by the
  owner from the Epic launcher (Fab library → Install to Engine 5.8); its licence does not allow redistribution, so it
  stays out of the repository.
- **This machine cannot run it**: GTX 1050 Ti, D3D12 `RaytracingTier` 0 (checked with a small D3D12 probe); UE 5.8 turns
  ray tracing on only with tier 1.1 + bindless (`Runtime/D3D12RHI/Private/D3D12Adapter.cpp:1300-1337`). The level is
  built and configured here; listening is done on an RTX machine (owner's decision).
- **Steam Audio** (Valve, Apache 2.0): latest release v4.8.1 (11.02.2026); its Unreal docs ask for "Unreal Engine 4.27 or
  later" and there is no 5.8-specific build, so the plugin is built from the sources it ships with
  (`steamaudio_unreal_4.8.1.zip`, SHA-256 bab5119f…7e8f6b). The engine still carries the deprecated Steam Audio
  2.0-beta.17 under `Engine/Plugins/Runtime/Steam/SteamAudio`; the project copy wins
  (`Runtime/Projects/Private/PluginManager.cpp:1280`, "favoring the project level plugin"), the engine is not touched.
- **Settings conflict**: both plugins want the project's spatialization slot. UE 5.8 keeps every registered spatializer
  once a default one is configured and switches at runtime: `FAudioDevice::SetCurrentSpatializationPlugin`
  (`Runtime/Engine/Private/AudioDevice.cpp:704`, registration at `:546-562`), exposed as
  `UGameplayStatics::SetActiveSpatialPluginByName` (`GameplayStatics.cpp:2013`) and the console command
  `au.spatialization.SetCurrentSpatialPlugin`. The other slots do not collide (Steam Audio: reverb + occlusion; Audio
  Tracing: source data override). Plan: **one** configuration and a per-level switch; the two-profile fallback of SPEC §6
  only if PIE shows that the plugins disturb each other.

## Deviations from SPEC / plan

1. **One configuration instead of two profiles** (SPEC §6 fallback not needed): the industry actor switches the active
   spatializer when its variant is activated (`UGameplayStatics::SetActiveSpatialPluginByName`) and the level-start one
   is restored at EndPlay. Checked in PIE for Steam Audio; for Audio Tracing it is checked once the plugin is installed
   (the log tells if its spatializer is not registered).
2. **Audio Tracing not installed / no DXR here**: GTX 1050 Ti (D3D12 RaytracingTier 0). Its level has the industry actor
   only; the actor logs and shows on the HUD "hardware ray tracing OFF" and "spatializer not registered". Without the
   plugin the source plays 2D (no attenuation asset) — not an Audio Tracing result.
3. **Content through the python commandlet**, not the editor MCP: the 5.8 MCP toolsets cannot call UFUNCTIONs (Prepare
   Level, the Steam Audio export) or run python. The commandlet exits with code 1 because of the engine's own
   `LogGameFeatures: Error: Asset manager settings do not include a rule for GameFeatureData` (present since M0) and the
   missing Audio Tracing class; the script itself reports "Python script executed successfully".
4. **Map copies by "Save As"**: `delete_asset` + `duplicate_asset` over the M0 placeholders failed in the commandlet (the
   force-deleted map stays in the asset registry), so the script saves the loaded `Level_Amphitheatre` under the target
   name (`EditorLoadingAndSavingUtils.save_map`).
5. **Arena floor stand-in** instead of the amphitheatre (Level_Amphitheatre was the M0 placeholder; the cavea is M10). With
   one floor plane Steam Audio has almost nothing to reflect, so the click metrics below are not meaningful yet.
6. **`bUseUnity = false`** in `AcousticsLab.Build.cs`: the new files regrouped the unity units and merged the UI widgets
   whose anonymous-namespace style constants share names (C2374). One translation unit per .cpp.
7. **Click recorder and the editor's background mute**: the editor mutes PIE when its window is not focused
   (`UEditorEngine::Tick`, `Editor/UnrealEd/Private/EditorEngine.cpp:1906-1925`, unless *Allow Background Audio*); a
   recording then is pure silence. The recorder lifts `ULevelEditorMiscSettings::bAllowBackgroundAudio` and
   `FApp::UnfocusedVolumeMultiplier` (`Runtime/ApplicationCore/Private/Windows/WindowsPlatformApplicationMisc.cpp:259`)
   for the measurement and restores them (the editor setting is not saved). `AcousticsLab.Build.cs` adds `UnrealEd` for
   editor targets only.
8. **Steam Audio simulation settings** left at the plugin defaults (real-time: 1.0 s IR, 4 bounces, 4096 rays,
   `USteamAudioSettings`, config=Engine); worth raising (2 s / 8 bounces) once the cavea exists (M10).
9. **Runtime switch between the plugins** (owner's request, 16.10.2026; SPEC §3.7 / the plan had "5 and 6 only in their
   levels"): both industry levels hold a Steam Audio and an Audio Tracing industry actor; the level's own plugin starts,
   key 5 / 6 switches to the other plugin during play (`AIndustryAudioActor::HandleVariantKeyInWorld`: the other source
   stops, the spatializer follows, the listener receiver is kept), keys 1-4 go back to our convolution variants. Both
   levels carry the Steam Audio geometry (static geometry `SAG_<level>`) and, once installed, the Audio Tracing sound
   materials. The two levels differ only in which plugin starts and in the main-menu entry.

## How to verify / listen by hand

1. Open `Level_Amphitheatre_SteamAudio`, Play. HUD line 3 (yellow): `5: Steam Audio  6: Audio Tracing`, the active
   plugin's spatializer, source S1, listener R1, playing. Keys 5 / 6 switch between the plugins while playing (Audio
   Tracing is only real on an RTX machine with the plugin installed).
   Headphones: the anechoic test signal from the arena centre, binaural (HRTF), with the floor reflection.
2. Console: `Acoustics.Industry.Receiver R3` moves the listener to the last row (quieter, later); `R4` to the side
   sector. `Acoustics.Industry.State` prints the state. Keys 1–4 return to our convolution variants, 5 / 6 back to a plugin.
3. `Acoustics.Industry.MeasureClick` (≈ 22 s): clicks at R1..R4, metrics in the log and in the compare panel (H).
4. **Audio Tracing (RTX machine)**: install *Audio Tracing* from the Epic launcher into UE 5.8 (Fab library → Install to
   Engine). Then (a) add `{"Name": "<its plugin name>", "Enabled": true, "Optional": true}` to `AcousticsLab.uproject`,
   (b) set `SourceDataOverridePlugin=<its display name>` in `Config/DefaultEngine.ini`, (c) check the `TRACING_*`
   constants in `Tools/Editor/create_m9_content.py` against its headers (class paths of the sound material asset and
   component, property names), (d) run the script with the phases `assets steam tracing` (editor closed; both levels get the sound materials), (e) open
   `Level_Amphitheatre_AudioTracing`, Play: the log must show `spatializer ... -> Audio Tracing Spatializer (switched)`
   and no "ray tracing OFF" warning; listen at R1..R4, switch 5 / 6 for a direct A/B of the two plugins, then
   `Acoustics.Industry.MeasureClick` with each plugin active for the SteamAud / AudioTr columns (it measures the active one).
