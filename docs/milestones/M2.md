# M2 — stochastic ray tracer, room metrics, shoebox validation

## Plan

1. `AcousticsCore/Results`: `FEnergyHistogram` (1 ms bins, T_max 3 s, `Acoustics::NumBands` energies per bin, bin-major layout, `AddEnergy` / `Accumulate` / range sums), `FRoomMetrics` + `RoomAcoustics` helpers (Schroeder EDC in dB, EDT / T20 / T30 by least-squares regression over the dB range, C50 / C80 / D50 / Ts relative to the direct-sound arrival, Sabine and Eyring T60), `FSimulationResult` (per-receiver histogram + metrics + direct-sound data, path samples capped at `MaxPathsForVisualization`, timing, counters) and `FSolverProgress` (atomic progress + cancel flag).
2. `AcousticsCore/Solvers`: `FRayTracerSettings` (plain struct, the core side of SPEC §3.5 `FSolverSettings`) and `FRayTracer::Run(scene, source, receivers, settings, progress)` per SPEC §2.2: Fibonacci-sphere emission, `E0 = 1/N`, closest hit through the BVH (brute force when `bUseBVH` is off), `E *= (1 - alpha)`, Lambert-diffuse reflection with probability `s` else specular, optional air absorption `exp(-m d)`, transparent receiver spheres (energy deposited at the entry time, ray continues), analytic direct sound `r^2 / (4 d^2)` with an occlusion check (order-0 segments therefore skip the receiver test), termination at `E < E0 * 1e-6`, `t > T_max`, `order > MaxOrder`. Rays are processed in fixed chunks with per-chunk histograms summed in chunk order and a per-ray PCG32 stream seeded from (seed, ray index), so the result is bit-identical for any thread count.
3. `AcousticsLab/Simulation`: `FSolverSettings` (USTRUCT with the SPEC §3.5 fields, `ToRayTracerSettings()`), `AAcousticSimulationManager` (one per level: extracts the scene through `ALevelSetupActor::SceneExtractor`, optional wall-absorption override for the validation, launches `FRayTracer` with `UE::Tasks::Launch`, polls progress in `Tick`, publishes the result on the game thread, Sabine / Eyring reference from `AShoeboxRoomActor` + area-weighted mean absorption), `UAcousticSimulationSubsystem` (GameInstanceSubsystem: results per level / solver, last settings).
4. `AcousticsLab/UI/USimulationHUDWidget`: built in C++ like `UMainMenuWidget` (BindWidgetOptional slots for a future `WBP_SimulationHUD`): settings fields, Run / Stop, receiver selector, metrics of the selected receiver, timing, analytic Sabine / Eyring values and the deviation. `AAcousticsPlayerController` creates it in scene levels and toggles cursor / fly mode with Tab.
5. `Level_Shoebox`: place `AAcousticSimulationManager` through the editor's MCP server; `FindOrSpawn` as a fallback for levels without one.
6. Tests (`Source/AcousticsCore/Private/Tests/`): `AcousticsLab.Core.Metrics.SyntheticDecay`, `AcousticsLab.Core.Solvers.ShoeboxSabine` (alpha 0.1 / 0.2 / 0.3, 20k rays, T30 within 20 % of Eyring), `AcousticsLab.Core.Solvers.Deterministic` (same seed → identical histogram, other seed → different), `AcousticsLab.Core.Solvers.ThreadCountInvariance` (1 vs 4 workers).
7. Build, tests, validation table, this document, commit `M2: ray tracer, metrics, shoebox validation`, push.

## Validation (shoebox 10 x 7 x 3 m, V = 210 m³, S = 242 m², 20 000 rays, seed 20261015, order ≤ 200, no air absorption)

Source S1 (−3, −1.5, 1.5) m; receivers R1 (3, 1.5, 1.5) m and R2 (0, 2.5, 1.2) m, r = 0.5 m. T30 from the Schroeder curve by regression over −5…−35 dB. Trace times on 10 task-graph workers.

Diffuse walls, s = 1.0 (the field Sabine / Eyring assume) — the acceptance criterion (≤ 20 %) is tested on these rows:

| α | Sabine, s | Eyring, s | T30 R1, s | dev. R1 | T30 R2, s | dev. R2 | trace |
|---|---|---|---|---|---|---|---|
| 0.1 | 1.397 | 1.326 | 1.359 | +2.5 % | 1.358 | +2.4 % | 0.24 s |
| 0.2 | 0.699 | 0.626 | 0.658 | +5.1 % | 0.653 | +4.3 % | 0.13 s |
| 0.3 | 0.466 | 0.392 | 0.421 | +7.5 % | 0.426 | +8.8 % | 0.09 s |

Almost specular walls, s = 0.1 (the Concrete preset), reported for comparison only:

| α | Sabine, s | Eyring, s | T30 R1, s | dev. R1 | T30 R2, s | dev. R2 | trace |
|---|---|---|---|---|---|---|---|
| 0.1 | 1.397 | 1.326 | 1.499 | +13.0 % | 1.507 | +13.7 % | 0.33 s |
| 0.2 | 0.699 | 0.626 | 0.796 | +27.1 % | 0.776 | +23.9 % | 0.17 s |
| 0.3 | 0.466 | 0.392 | 0.533 | +36.1 % | 0.539 | +37.5 % | 0.12 s |

Reading: with Lambert walls the simulated T30 sits 2–9 % above Eyring and grows with α exactly as Kuttruff's free-path-variance correction predicts (the decay is a mixture of rays with different reflection counts, so it is slightly slower than the Eyring exponential). With specular walls a rectangular room is not diffuse: rays grazing along the 10 m axis hit walls at a third of the mean rate and dominate the late decay, so T30 exceeds Eyring by up to 36 % — the classic non-diffuse shoebox result, not a solver error. In the editor the same comparison is available with the "Wall alpha override" field (keep the room's Concrete s = 0.1, or set the room material to a scattering one).

Synthetic decays (test `SyntheticDecay`, T60 = 0.4 / 1.2 / 2.0 s, bin integrals of exp(−k t)): EDT, T20 and T30 reproduce T60 to better than 0.1 % (criterion 2 %), C50 / C80 match the closed form 10·log10((1 − e^(−k·0.05)) / (e^(−k·0.05) − e^(−k·3))) to 1e-6 dB, D50 and Ts to the closed form. A decay truncated at −42 dB yields no T30 (needs −35 dB plus the 10 dB margin) but a valid T20 within 2 %.

## Deviations from SPEC / PROMPTS

- The 20 % Eyring criterion is asserted for diffuse walls (s = 1). The task text does not fix the scattering coefficient; Sabine / Eyring are diffuse-field formulas, and the specular room misses the criterion for physical reasons (table above). Both variants are in the test output.
- The validity of a decay time needs the usable Schroeder curve to reach the end of the fit range plus `ValidityMarginDb` = 10 dB, and the last `TruncationGuardSeconds` = 50 ms before the final non-empty bin are excluded from every fit (the backward integral plunges at a truncation). Without this, a histogram that simply stops produced a steep, meaningless T30. `FBandMetrics::DecayRangeDb` reports the usable range.
- The core settings struct is `FRayTracerSettings` (plain C++), the USTRUCT `FSolverSettings` lives in the game module and converts to it; the same name in both modules would clash. Later solvers get their own core structs filled from the same USTRUCT.
- Order-0 ray segments never deposit energy: the direct sound is added analytically (SPEC §2.2.7), otherwise it would be counted twice. `bAnalyticDirectSound = false` restores the pure stochastic behaviour (used by nothing yet).
- The scattering decision uses band 0 (`NumBands = 1`); with six bands one geometric ray cannot follow a per-band choice — noted in `RayTracer.h` for the band extension.
- `FSolverSettings::ReceiverRadius` > 0 applies to every receiver; 0 keeps each `AAcousticReceiver::RadiusMeters`. `NumThreads` is honoured through `ParallelFor` work items (0 = all workers); the dedicated `FQueuedThreadPool` with an exact thread count arrives with M7.
- `WallAbsorptionOverride` on the manager (not in SPEC) replaces the absorption of every extracted material for the validation runs in the editor; the Sabine / Eyring values in the HUD follow it.
- The simulation panel starts in cursor mode so the HUD is usable at once; Tab switches to mouse look (M0 started in fly mode).
- Build note: the first full build compiled everything (159 s) and failed only at link time because the editor still held the DLLs — `taskkill /PID` in Git Bash turns `/PID` into a path and does nothing. Close the editor with PowerShell `(Get-Process -Id <pid>).CloseMainWindow()` (recorded in `docs/ENV.md`).
