# M1 — geometry, BVH, scene extraction

## Plan

1. `AcousticsCore/Geometry`: `FAcousticTriangle` (meters, double, right-handed front normal `(V1-V0)x(V2-V0)`), `FAcousticMaterialProps` (arrays sized `Acoustics::NumBands`), `FMedium` (air/water, impedance), `FAcousticRay`/`FRayHit`/Möller–Trumbore in `RayIntersection`, `FAcousticFrustum` (planes of a triangular beam), `FBVH` (median split on the longest centroid axis, leaves of 4–8 triangles, `IntersectRay` / `QueryAABB` / `QueryFrustum` + brute-force counterparts), `FAcousticScene` (triangles, materials, media, BVH, `MakeShoebox` helper, segment occlusion test).
2. `AcousticsLab/Scene`: `UAcousticMaterialAsset` (DataAsset; `ApplyPreset` from a C++ preset table shared with the extractor), `UAcousticSceneExtractorComponent` (StaticMesh / InstancedStaticMesh / DynamicMesh components tagged `Acoustic`, RenderData LOD0, world transform, cm → m, UE winding → core winding, mirrored transforms, material by `AcMat:<name>` tag → asset library → preset table → default Concrete), `AAcousticSource`, `AAcousticReceiver`.
3. `AcousticsLab/Levels`: `AShoeboxRoomActor` (six single-sided 100×100 cm quads scaled to the room size, inward normals via `FRotationMatrix::MakeFromZX`, tags set in `RebuildRoom`), `ALevelSetupActor` gets the extractor component and a "Log Extracted Scene" editor button.
4. Content: six `DA_AcMat_*` presets under `Content/Acoustics/Materials`, `Level_Shoebox` rebuilt with the room, a source, two receivers, a point light and the PlayerStart inside the room. Planned as a headless python commandlet; changed mid-milestone to the editor's own MCP server at the owner's request (see Deviations).
5. Tests: `AcousticsLab.Core.Geometry.RayTriangle`, `BvhMatchesBruteForce` (10k random rays on 4k random triangles + the shoebox), `BvhQueriesMatchBruteForce` (AABB / frustum), `ShoeboxScene` (core helper), `ShoeboxExtraction` (transient world + room actor → 12 triangles, 242 m² ± 0.1, inward normals, materials).
6. Build, tests, this document, commit `M1: geometry, BVH, scene extraction`, push.

## Deviations from SPEC / PROMPTS

- The content step was done with the editor's MCP server (`SceneTools`, `ObjectTools`, `DataAssetTools`, `AssetTools`) instead of a python commandlet, at the owner's request during the milestone. No `Tools/Editor/build_shoebox_level.py` exists.
- "6 slabs" are six single-sided quads (engine `/Engine/BasicShapes/Plane`, 2 triangles each), so the extracted room is exactly 12 triangles and the room can be inspected from outside in the editor (back faces culled). The engine plane has no "Allow CPU Access", which is fine for editor/PIE/standalone (uncooked builds always keep CPU buffers: `StaticMesh.cpp`, `bNeedsCPUAccess = !RequiresCookedData() || bAllowCPUAccess`); a packaged build would need a custom quad with the flag (SPEC §6 accepts the editor-only limitation). `AShoeboxRoomActor::WallMesh` is editable for that.
- `AcousticsLab.Core.Geometry.ShoeboxExtraction` lives in the game module (`Source/AcousticsLab/Private/Tests/`) because it needs a world, actors and a static mesh; it spawns `AShoeboxRoomActor` into a transient `UWorld` instead of loading the map. It also checks the `AcMat:Wood` resolution through the preset table.
- Core triangles use the right-handed normal `(V1-V0)x(V2-V0)`; UE meshes (static and dynamic) use `(V2-V0)x(V1-V0)` (`StaticMeshOperations.cpp`, `VectorUtil::Normal`), so the extractor swaps V1/V2 on import and swaps back for mirrored transforms.
- The extractor also accepts the actor tag `Acoustic` (all mesh components of the actor) and instanced static meshes (one copy per instance); `UAcousticMaterialAsset` keeps `TArray<float>` bands with `EditFixedSize` instead of a C array (UHT cannot size arrays by `Acoustics::NumBands`).
- Material presets exist twice by design: the DataAssets (what the level references) and the C++ table (fallback when a tag names a preset without an asset, and the source of `ApplyPreset`). WaterSurface coefficients (α 0.01, s 0.05) are not in SPEC; chosen as "almost total reflection from the air side".
- Source/receiver positions for the shoebox are not in SPEC (§3.4 fixes only the amphitheatre); chosen S1 (−3, −1.5, 1.5) m, R1 (3, 1.5, 1.5) m, R2 (0, 2.5, 1.2) m.
- Repo hygiene: `.swarm/` and `.claude-flow/` (ruflo state) added to `.gitignore`; `.mcp.json` committed so new sessions get the editor connection.
- Build note: the first full build failed to link while an editor still had the project open (`LNK1104` on `UnrealEditor-AcousticsCore.dll`); `Build.bat` needs the project closed in every editor instance.

## Verify in the editor

1. Open the project and `Level_Shoebox`. Expected: a grey 10 × 7 × 3 m room visible from outside (single-sided walls), `SourceS1` and `ReceiverR1`/`ReceiverR2` as small spheres (receivers with a 0.5 m wireframe sphere), `RoomLight`, the PlayerStart inside.
2. Select `LevelSetup` → Details → Acoustics → **Log Extracted Scene**. Output Log (`LogAcoustics`): `12 triangles (0 degenerate skipped), 242.000 m^2, 1 materials; 1 actors, 6 static mesh components …` and `material 0 "Concrete": alpha 0.030, s 0.100`; the viewport draws the triangle edges and cyan normals pointing into the room for 10 s.
3. Select `ShoeboxRoom` → change `Room Size Meters` or `Material Name` (e.g. `Wood`) → the walls rebuild; **Log Extracted Scene** again shows the new area / material.
4. Content Browser → `Acoustics/Materials`: six `DA_AcMat_*` assets; `DA_AcMat_Audience` has α 0.7, s 0.6; `DA_AcMat_WaterSurface` has `bInterface` on.
5. Play (Standalone or PIE): you spawn inside the room facing the source; the walls block movement (BlockAll).
6. Tests: Tools → Session Frontend → Automation → filter `AcousticsLab` → 6 tests pass. Headless: the test command in `CLAUDE.md`.
