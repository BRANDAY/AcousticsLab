## Unreal MCP (recorded at M1)

- Plugins `ModelContextProtocol` (server), `AllToolsets` (editor toolsets: scene/actor/object/asset/data-asset tools, automation tests) and `MCPClientToolset` are enabled in `AcousticsLab.uproject`. `.mcp.json` next to the `.uproject` points Claude Code at `http://127.0.0.1:8000/mcp`.
- The server does not start by itself: launch the editor with `UnrealEditor.exe AcousticsLab.uproject /Game/Maps/Level_Shoebox -ModelContextProtocolStartServer -ModelContextProtocolPort=8000`, or run `ModelContextProtocol.StartServer` in the editor console (or set `bAutoStartServer=True` in Editor Preferences). With tool search on, the MCP surface is `list_toolsets` / `describe_toolset` / `call_tool`; objects are passed as `{"refPath": "/Game/Maps/Level_Shoebox.Level_Shoebox:PersistentLevel.Actor_0"}`, classes as `{"refPath": "/Script/AcousticsLab.ShoeboxRoomActor"}`.
- Limits seen in 5.8: no tool calls a UFUNCTION (use `ObjectTools.set_properties` with a JSON string), no save-level tool (`AssetTools.save_assets` with `[]` saves every dirty package including the map), Live Coding needs the `LiveCodingToolset` plugin (not part of `AllToolsets`). `Build.bat` cannot link while an editor has the project open.
- The server exposes exactly three MCP tools: `list_toolsets`, `describe_toolset {toolset_name}` and `call_tool {toolset_name, tool_name, arguments}` — `tool_name` is the short name without the toolset prefix (e.g. toolset `editor_toolset.toolsets.scene.SceneTools`, tool `add_to_scene_from_class`); the fully qualified name is rejected with "Tool not found". `ObjectTools.set_properties` takes `values` as a JSON *string* and accepts nested struct members (`{"Settings": {"MaxOrder": 500}}`); `EditorAppToolset.StartPIE {options: {}}` / `StopPIE` / `IsPIERunning` drive PIE, `LogsToolset.GetLogEntries {category, pattern, maxEntries}` reads the output log (first line of multi-line messages only; the full text is in `Saved/Logs/AcousticsLab.log`). `EditorAppToolset.CaptureViewport` returns the *editor* viewport as base64 PNG inside the JSON text (`returnValue.image.data`), not the PIE window.
- Without the native connector (it attaches only at session start; after an editor restart its `call_tool` may answer "Tool not found" even though `describe_toolset` works), `Tools/Editor/mcp_client.py` talks to the same server over Streamable HTTP: `python Tools/Editor/mcp_client.py toolsets | describe <toolset> | call <tool> '<json args>'`, or import `McpClient` from a script and use `call("call_tool", {...})` (recorded at M2, see the scripts in `docs/milestones/M2.md`).

- **Content through MCP**: `Tools/Editor/create_m3_content.py` shows the `MaterialTools` recipe (`create_material {folder_path, asset_name}`, `add_expression {material_or_function, expression_class: {refPath}, x, y}`, `ObjectTools.set_properties` on the expression, `connect_to_output {expression, output_name: "", material_property: "MP_EmissiveColor"}`, `recompile`, `get_expressions` to find existing nodes, `AssetTools.exists {path}`) and the `SceneTools.add_to_scene_from_class` + `set_properties` + `AssetTools.save_assets []` sequence for an actor. Shapes that matter in 5.8.3: every tool answers `{"returnValue": ...}`; `find_actors` needs all of `name`, `tag` ("") and `collision_channels` ([]); the `add_to_scene_from_class` transform is `{location: {x, y, z}, rotation: {pitch, yaw, roll}, scale: {x, y, z}}`; actor refPaths use the class name without the prefix (`...PersistentLevel.AcousticSimulationManager_0`, `...PersistentLevel.ReceiverGrid_0`) and components hang off them (`...ReceiverGrid_0.Heatmap`); `StartPIE {options: {playMode: "PlayMode_InViewPort"}}`; editor messages come in the editor's locale (Russian here), so never parse error text — query state (`AssetTools.exists`) instead. A material used on an instanced static mesh wants `bUsedWithInstancedStaticMeshes: true`.
- **Build times**: a header included by most of the game module (the HUD widget) forces a near-full rebuild of `AcousticsLab`; with the editor's project browser open the machine allows 3 parallel actions and that rebuild took 13 min. Changing only .cpp files rebuilds in ~2.5 min. `-Module=AcousticsCore` restricts a build to the core module (75 s) for an early check of solver changes.
- **Claude Code Bash tool**: a command containing an apostrophe anywhere (even inside a quoted heredoc) fails before running; put multi-line scripts into a file and run `python file.py`.

## Closing the editor from a script (recorded at M2)

- `taskkill /PID <pid>` does not work from Git Bash: MSYS rewrites `/PID` and `/F` into paths (`F:/`) and the command fails, so the editor keeps the DLLs locked and `Build.bat` dies with LNK1104. Use PowerShell instead: `$p = Get-Process -Id <pid>; $p.CloseMainWindow(); $p.WaitForExit(90000)` (graceful; `Stop-Process -Force` only as a fallback). Renaming a loaded DLL succeeds on Windows, so a "move" test does not prove the file is free.
- Relaunch for MCP work: PowerShell `Start-Process UnrealEditor.exe -ArgumentList '"<project>.uproject"', '/Game/Maps/Level_Shoebox', '-ModelContextProtocolStartServer', '-ModelContextProtocolPort=8000'`, then wait for `http://127.0.0.1:8000/mcp` to answer (about a minute).
